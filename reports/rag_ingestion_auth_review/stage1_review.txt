═══ 三、人工审查结果 ═══

逐条核对计划 1.2 的五项实现要求：

[√] 1. 从 Authorization: Bearer <JWT> 读取身份
       auth_service._extract_bearer_token 只接受 Bearer 方案；
       Basic / Token / 空令牌 / 缺头一律 401。测试覆盖 6 种畸形头。

[√] 2. 校验签名、发行方、受众、过期时间和 tenant_id claim
       decode_access_token 显式传 algorithms=[config.algorithm]（白名单，含 none 拦截）、
       issuer、audience、leeway、options={"require": ["exp","iss","aud","sub"]}；
       tenant_id 由 build_auth_context 单独校验，缺失即 401。
       参数化测试覆盖 9 种非法令牌：过期 / iss 错 / aud 错 / 签名错 / 缺 exp /
       缺 aud / alg=none / 空串 / 非 JWT。

[√] 3. 测试环境使用专用测试密钥；生产密钥只从环境变量读取
       load_auth_config 只读 RAG_JWT_SECRET；缺失且未显式打开
       RAG_ALLOW_TEST_JWT_SECRET 时抛 AuthConfigError（fail closed，非降级放行）。
       测试更进一步：conftest.py 强制写入本进程随机密钥，**产品代码里不存在
       任何可用于签发的密钥**；另有测试断言生效密钥来自环境变量且不等于内置常量。

[√] 4. X-User-Role 不参与鉴权；兼容期仅可记录，不可授权
       auth_service._warn_on_legacy_headers 只记日志（实测日志已确认输出），
       返回值完全不进入 AuthContext —— AuthContext 只装已验证的 claims。
       负向测试：
         · 只发 X-User-Role: admin 不发令牌           → 401
         · agent 令牌 + X-User-Role: admin 打管理接口 → 403（且 whoami 仍返回 agent_1）
         · 令牌自报 scopes/permissions（伪造提权）    → 403，且 scopes 被忽略
       另外补了一条计划没写但同类的问题：token 里的 scopes / permissions claim
       一律忽略，权限只能由服务端按 roles 推导。否则持有合法令牌的人可自报权限提权。

[√] 5. 缺失/过期 token 返回 401，租户或资源不匹配返回 403 或不泄漏存在性的 404
       401：缺头/空头/非 Bearer/畸形/过期/签名错/iss 错/aud 错/缺 claim
       403：认证通过但 scope 不足；未登记的 operation 对所有人 403（fail closed）
       404：跨租户资源 —— 与「资源不存在」返回**完全相同的状态码与响应体**，
            并有专门断言证明两者不可区分，且响应里不含其他租户的标题与 id
       500：服务端未配密钥（服务端故障不判成用户 401），测试已覆盖

阶段 1 额外加固（计划未显式要求，但属于同类风险且已有测试）：
  · ROLE_SCOPES 由授权表 inversion 推导，并有测试断言两者严格同构，
    防止「改了表忘了改推导」导致权限静默漂移
  · AuthContext 不可变（dataclass frozen）+ 空 user_id/tenant_id 构造即拒
  · primary_role 取字典序最小，保证审计角色记录不抖动
  · 审计 request_id 改为使用 HTTP 请求追踪号（X-Request-Id 或新生成 uuid），
    业务对象 id 仍走 object_id 字段，信息量只增不减
  · 客户端在请求体里自报的 operator_id / operator_role 会被 JWT 身份覆盖，
    旧实现会原样采信（属于同类信任边界问题，一并收紧）

═══ 四、风险与回滚点 ═══

风险 1（已存在，未消除）：本机无 Docker / 无 PostgreSQL，迁移只在 SQLite 上实测。
  缓解：迁移按方言无关写法；docker-compose 已补 postgres:16 + redis:7；
        连接串只走 RAG_DATABASE_URL。仍需在真实 PostgreSQL 上复验一次。
风险 2（新增，需注意）：这是一次**破坏性接口变更**。
  仍按 X-User-Role / X-Operator-Id 调用的旧客户端会全部收到 401。
  缓解：现有前端/脚本需换成 Bearer 令牌；兼容期日志会打印告警便于排查。
        /docs 已声明 bearerAuth，联调方可以直接在 Swagger 里贴令牌。
风险 3（新增）：令牌签发方尚未实现（本期只做校验）。
  当前依赖外部签发 JWT（claims 需含 sub / tenant_id / roles / iss / aud / exp）。
  阶段 4 接 OIDC 时不需要改动校验逻辑。

回滚点：本阶段改动集中在
  services/auth_context.py（新增，可删）
  services/auth_service.py（重写，可从 git 恢复）
  main.py、11 个 routers、8 个测试文件、tests/conftest.py、tests/auth_helpers.py
数据库侧只有 alembic/versions/0001 与 services/ingestion/*，与鉴权改动互不耦合，
可分别回滚。回滚命令（需用户确认后执行）：
  git checkout -- services/auth_service.py main.py routers/ tests/
  rm -f services/auth_context.py tests/conftest.py tests/auth_helpers.py
